## Developer responsibilities
Claude and Codex are peer developers. Each plans bounded work, maintains claims/handoffs, resolves CI, and handles eligible merges. **Cross-review is targeted, not universal.** Neither requires routine manager ACK for an already authorized disjoint task or eligible low-risk PR.
- Codex normally leads engine/save/region/resource compatibility; Claude normally leads approved maps/content and genuine mGBA QA. These are defaults, not exclusive expertise.
- **Fast Lane A — low-risk author self-merge (R0/R1):** non-draft PRs containing only docs, trackers, design proposals or isolated test/QA tooling (no production code, map data, saves/IDs, protected files or workflows), after applicable checks, meaningful evidence with exact head/paths/tests, and SHA-expected normal merge. A design merge authorizes no permanent construction.
- **Fast Lane B — bounded owner-approved production additions (narrow R2/R3 exception):** a non-draft PR may also be self-merged when its complete production diff is limited to a *specific, preapproved* small map/connection/script plus mechanical registry/test changes, including **an append-only section or healer identity whose exact value the owner already approved**. This exception explicitly includes #150 Route201/section217 and #151 Sandgem healer44 **only after** their unfinished acceptance/hand-off work is completed. It is never a blanket exception for future sections/healers.
  - Owner approval of **each** geography/identity/detail is traceable; no new invented map/canon/encounters/IDs. Every existing protected-path check and the exact PR-specific literal `HANDOFF_APPROVED` are satisfied. No path collision, changed existing ID meaning, save layout/encoding/migration, broad engine refactor, workflow/guard/security or release change.
  - Real NORMAL/RELEASE builds on the changed source; native/negative/save-compatibility checks where applicable; genuine mGBA checks for player-visible changes (including correct seam/warps, natural respawn where applicable, and **Save → fresh-process Continue**). Log source/ROM hashes, growth/headroom, and fixture limitations. These are conditions, not automatically waived because an earlier candidate/dry-run passed.
  - All applicable newest checks pass; author inspects exact final diff against refreshed main and provides a substantive exact-head evidence comment naming changed paths, real pass/fail/skip counts and unknowns. Then the author may personally perform a normal SHA-expected merge and verify main. **Independent peer review is optional, not blocking for this lane.** If any criterion fails, return to an independent review/owner decision rather than bypass it.
- **Peer review remains mandatory** for unapproved, reused or reassigned permanent identities; save layout/schema/encoding/migrations; broad or cross-system engine/runtime changes; unapproved permanent world geometry; major assets/mass updates; protected governance instructions, CI/workflows/guards, security or release changes; or any change with unresolved preservation/test risk. The nonauthor peer documents the actual reviewed production diff and risk. Shared GitHub login cannot itself prove independent identity, so attribute reviewers in prose. **One substantive review per changed production code state is enough**: docs-only/evidence-only follow-up commits do not require duplicate code inspection if the production source identity is unchanged and new checks remain applicable. Once reviewed, the author may execute the pinned merge; the reviewer need not be the one to click Merge.
- A rotating integration steward may check collisions, current heads and eligibility, but does not create a manager gate. Fast Lane A/B authors may integrate their own eligible work; consequential review-required changes remain reviewed before normal merging.
- Respect existing paused sessions and reserved work. GitHub comments do not launch agents or authorize paid execution.

## Claims and handoffs
Post one scoped claim in #15:
`CLAIM | developer | branch/PR | literal paths | intended outcome | evidence | dependencies`.
Check live PR file lists and existing claims first. File-disjoint approved work proceeds immediately. Serialize the actual collision, including generator inputs and outputs; preserve dirty worktrees and every contributor's commits. Release a claim after merge, explicit transfer or abandonment.
A protected-path change requires a genuine authorized `HANDOFF_APPROVED PR=#N PATHS=literal,comma-separated,paths` matching that PR. No globs or directory-only handoffs. Content/map approval must precede its handoff. Do not fabricate approvals; obey the existing checker and its trusted-author rules.
At a session end, push recoverable work and leave one PR HANDOFF with remote full SHA, files, changes, exact commands and PASS/FAIL/SKIP counts, source/ROM hashes, fixture use, remaining risk, next executable action, and `WAITING_ON / RESUME_WHEN` when blocked. Do not rewrite shared status docs for each test run.

## Risk and review gates
| Tier | Scope | Minimum gate |
| --- | --- | --- |
| R0 | Prose, tracker, documentation or design **proposal only** | **Self-merge allowed** after exact-head author evidence, applicable guards and relevant link/content checks. A proposed route is not approved for production merely because its design document merged. |
| R1 | Isolated test/QA tooling and test-only experiments, no production source or reserved path | **Self-merge allowed** after meaningful passing positive/negative tests with nonzero counts, exact-head evidence and all applicable checks. New code in production engine files is **not** R1, even if small. |
| R2 | Routine bounded runtime, map and game-data changes | **Fast Lane B self-merge only when each proposed detail was owner-approved and the exact scope, protected handoff, native/build, authentic mGBA and save/Continue evidence are complete.** All other R2 work needs peer review. |
| R3 | Permanent identities, saves, protected policy/workflows/CI, release/security | **Peer review required by default.** The *only* self-merge carve-out is an owner-approved **append-only exact section/healer ID** bundled with a small approved map/respawn addition meeting every Fast Lane B safeguard. Any changed/reused ID meaning, schema/migration, broader engine, governance, CI, guard, release or security change still needs independent review. |

Tier is about impact, not file extension: executable workflows are R3; a design proposal can be reviewed as a proposal without authorizing construction.

Before merging (whether self-merge or peer-merge): refresh both full head and base SHAs, inspect the final diff and collisions, ensure non-draft, verify required checks and every applicable test. Publish exact-head evidence and pin the merge to that head; do not merge if the commit moved unexpectedly. Changes to reviewed production content require refreshed source review when the peer gate applies. A later docs-only/evidence-only commit does not force repeated review of unchanged production source, but all applicable final-head CI/evidence must remain current. Choose newest applicable check per workflow/job; a superseded canceled run is not a current failure, but missing/pending/skipped required checks are not PASS. Where integration changes tested behavior, reconcile in the feature branch or verify a disposable combined tree and record exact revisions. Never rely only on a mergeable flag.
Use the normal PR path, preserving history. Never direct-push main, force-rewrite shared branches, bypass rules, disable guards, change failure baselines to hide failures, or merge known failures. Verify main after merge and stop the affected integration lane on a regression. Preserve the prior good commit and repair or revert through a reviewed PR.
After integration, release claims and update the queue at a real status/dependency change. Do not mark a whole feature accepted from a partial test.

## Owner-only decisions
The owner retains geography and reference deviations, route openings, plot/canon, dialogue direction, Gym/trainer rosters, encounters/legendary placement, level curves/caps, art/music rights and personal likenesses, permanent map/section/heal/flag identities, origin encoding precision/migration policy, default cry-profile adoption and final release/Delta acceptance.
Developers present a bounded recommendation with alternatives and implications. They may autonomously implement already approved details, safe generic repairs, tests and tooling; approval of one map is not approval of every route.
Current decisions awaiting the owner are listed once in the [queue](INTEGRATION_QUEUE.md). Routine review, CI repair, claim arbitration and merge eligibility belong to developers.
