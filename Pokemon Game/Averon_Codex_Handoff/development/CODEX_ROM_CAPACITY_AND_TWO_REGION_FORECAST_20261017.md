## Authoritative baseline / what NOT to double count
The previously verified 2026-10-17 NORMAL/RELEASE builds were **26,736,200 B / 26,854,924 B linked**, with **6,699,508 B RELEASE headroom** under 32 MiB. This baseline is source-pinned in `SINNOH_TECHNICAL_READINESS_20261017.md` and must be remeasured on current main if engine inputs have changed.
Measured NORMAL linked inventory: `data/sound_data.o` audio `.rodata` **10,422,348 B**; cry blobs **9,386,416 B** across 1,156 linked blobs; 105 instrument/other blobs **642,204 B**; phoneme blobs **111,496 B**. Those sample subcategories are **inside** the audio object, not extra categories. `data/maps.o` **710,320 B**, `data/map_events.o` **103,692 B**, `src/tilesets.o` **688,440 B**; these are NORMAL object inputs, not an exhaustive map+story accounting and not additive with section totals. `.text` **2,348,792 B**; `script_data` **1,263,160 B**. Do NOT claim that disabling cries yields exactly 9,386,416 B in RELEASE without an actual differential build. The reported 5 MiB content-growth envelope was a **provisional planning scenario, not a tested forecast**.
Current engine build rules use 32M ROM linker at `engine/ld_script_modern.ld`; existing no-cry configuration is **real**:
- `engine/include/config/pokemon.h`: `P_CRIES_ENABLED TRUE` currently. `P_MODIFIED_MEGA_CRIES` is a separate possible partial saving.
- `engine/sound/direct_sound_data.inc` and `engine/sound/cry_tables.inc` wrap cry samples/tables in `P_CRIES_ENABLED`.
- `engine/src/pokemon.c` returns `CRY_NONE` in `GetCryIdBySpecies` when cries disabled; `engine/src/sound.c` checks for `CRY_NONE` before cry-tone playback.
These facts suggest a supported **cry-only** ROM trim while **music and other sound samples remain**. They do NOT prove every gameplay wait/cry-dependent event is safe. The upstream change `rh-hideout/pokeemerald-expansion` PR #4791 explicitly notes a Pokédex cry page caveat.
