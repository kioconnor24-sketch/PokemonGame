# Owner decision: reversible Pokémon cries-off policy (2026-10-17)

## Owner clarification — October 18, 2026

**The ordinary game build must default to cries OFF.** The owner explicitly reconfirmed: keep every cry source file in GitHub so cries can be restored later. `make` and `make RELEASE=1` therefore use `P_CRIES_ENABLED FALSE`; `make CRIES=on` / `make RELEASE=1 CRIES=on` remain explicit restoration builds. This is a build configuration, not an in-game toggle. Music and other sound effects remain enabled. Apply this correction through the normal tested PR process; a pending configuration PR does not mean main has already changed.

The safety implementation #117 and clinic fix #124 are merged. The historical cold-start failure below is resolved evidence, not an outstanding blocker or a reason to retain an ON default. Human listening and Delta remain separate deferred release checks. Older routing text saying “default ON” or “OFF adoption undecided” is superseded by this owner instruction and must be reconciled before pending routing proposals integrate.

## Owner intent (approved)
The owner **accepts playing Pokémon Averon without Pokémon cries, provided ordinary music and other sound effects keep functioning**, to recover cartridge storage. **The complete Pokémon cries collection must be retained in the source repository, with a reversible switch for restoring them to a build in the future if size/compatibility permits.** This is a **conditional build/content policy**, not authorization to irreversibly remove sources, corrupt audio-dependent flows, or ship an untested alternate ROM.

**Retention is mandatory:**
- Keep all existing `sound/direct_sound_samples/cries/**` sources, generated-asset inputs, cry definitions, lookup tables and species associations in version control. Do **not** delete or replace source cries with silence or discard unique Mega cries permanently.
- Do **not** ship hidden duplicate cry payloads in a no-cries ROM merely to preserve the option. Files stay in source; an OFF build excludes the linked cry bank. The ON build must be reproducible from the **same** source (plus build configuration), not require recovering deleted art/audio or restoring old commits.
- Prefer existing `P_CRIES_ENABLED` configuration and an auditable, explicitly selectable ON/OFF build profile; preserve the ability to set `P_CRIES_ENABLED TRUE` and produce an equivalent cries-ON build. Don't introduce a redundant new audio engine or fragile file deletion/restore workflow.
- Songs, music instruments, battle themes, victory/healing themes, fanfares, menu/field/move sound effects must remain. The cry-dependent sound cues can be silent only after graphical/runtime flow QA proves they don't crash/softlock.

## Exact current evidence and blocker
See [Codex measured capacity results](CODEX_ROM_CAPACITY_RESULTS_20261017.md), merged PR #115. Pinned prior RELEASE cried ON 26,854,924 linked B / free 6,699,508 B. Experimental cries OFF/music on 17,438,276 linked B / free 16,116,156 B: **9,416,648 B (8.980 MiB) exact saving**. This is a tested linked-byte **difference**, not an approved production game or guaranteed budget for all future content.

**Historical failure, resolved by merged #117:** in the original cries-OFF experiment, cold-start `gMPlay_PokemonCry` remained NULL and cry completion/stop APIs dereferenced it. Codex's original nonheadless RED evidence was ON **6/6 PASS** vs OFF **5 PASS / 1 FAIL**. Preserve that evidence; do not describe it as the current implementation's result. The unrelated unique-Mega-cries-only experiment also failed compilation and was not adopted. A passing build still does not claim human listening or Delta QA.

## Restoration feasibility is CONDITIONAL, not guaranteed
The full-game Codex **expected scenario** currently projects **+6,427,808 B available with cries OFF** after content and reserve, but **−2,988,840 B (≈2.85 MiB short)** with cries ON. Those future-content quantities are LOW-CONFIDENCE design estimates. Consequently, **retaining cry files and a reversible ON build path is achievable now; guaranteeing they can be enabled in a final 32 MiB full-content game is NOT currently established**. Later re-enable may require additional verified compression/reclamation, scope/budget changes, or a tested extended-ROM/emulator solution.
